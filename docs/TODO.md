- P1：保证现有实时监控链路可靠、数据正确和交付可恢复。
- P2：完成告警、探测、历史与主机管理的产品能力。
- P3：按实际需求和规模推进的增强项。
- 编号在拆分 Issue/PR 时保留；建议负责人按模块指定，不预设具体人员。任务拆分后先完成其列出的依赖。
- 每项完成需要代码、相应验证与现状文档；验收标准是实施时的要求，本次文档梳理未执行这些运行验收。

## P0：身份、租户授权与公开入口

- [x] **P0-01 私有读取与分享授权（master-api / Web，M0）**
  - 原始依据：主机列表、详情、SSE 和最新指标位于 public 路由；列表和 SSE 未传 tenant 时允许跨租户全量读取。最新快照虽校验主机归属，tenant 仍由匿名请求提供。
  - 工作：确定私有、演示和只读分享模式；私有租户来自会话，分享范围由可撤销凭据限定；所有读取入口统一执行授权。
  - 验收：未登录私有请求拒绝；用户 A 不能通过改 tenant/hostUID、省略 tenant 或建立 SSE 读取 B；公开分享不泄露非分享字段。依赖 P0-02 的会话创建能力，接口规则先确定。
  - 进展：2026-10-10 T03 完成上述本地实现与验收，分享/演示只返回授权主机/字段，秘密仅哈希存储，旧 Cookie/流到期或撤销后拒绝。具体证据见实施记录。

- [x] **P0-02 登录与管理员引导（master-api / Web，M0）**
  - 原始依据：已有会话存储、读取和退出，但没有创建会话的登录入口；`LoginPage` 显示“登录暂未开放”。
  - 工作：选定并实现一种登录方式，定义初始管理员、租户归属、身份绑定与失效规则；登录成功跳转只接受允许的站内目标。
  - 验收：新环境无需手工插入会话即可登录；禁用用户不能继续访问；退出使会话失效；回跳参数不能引向外站或未授权租户。
  - 进展：2026-10-10 T02 完成上述本地验收，文件、命令、截图与安全检查见实施记录和[登录手册](./02-guides/authentication.md)。

- [x] **P0-03 运维写入租户与操作者校验（master-api / 公共仓储，M0）**
  - 原始依据：维护窗和告警确认虽要求会话，仓储仍使用 `defaultTenantID`，操作者字段来自请求。
  - 工作：从会话传入可信租户/操作者，校验 scopeRef/alertID 归属、角色和资源存在性；保留审计记录。
  - 验收：非默认租户操作只作用于自身资源；跨租户 ID 被拒绝；伪造 CreatedBy/AckedBy 不改变真实操作者；不存在资源不返回成功。
  - 进展：2026-10-10 T03 运行时公共 PG 仓储已从可信 principal 执行租户/角色/资源校验与事务审计，覆盖非默认空间、越权和不存在资源；无调用的旧仓储在 T10 收敛。

- [ ] **P0-04 Agent / worker 凭据与身份绑定（Agent / ingest / master / 安装脚本，M0）**
  - 依据：gRPC 服务没有认证 interceptor；注册与指标由提交的身份字段驱动，事件/探测 HTTP 入口没有身份校验。
  - 工作：定义租户绑定的引导凭据、Agent/worker 身份、撤销与轮换；同时约束注册、单次 RPC、流式 RPC 和 HTTP 上报；更新安装配置权限与兼容升级说明。
  - 验收：知道 tenantCode/hostUID 也不能伪造注册、覆盖主机或上报；撤销凭据阻止新请求并终止或重新授权既有流；凭据不出现在日志、URL 或仓库。依赖 P0-01/P0-02 的租户权限模型。

- [x] **P0-05 会话与浏览器写操作安全（master-api / Web，M0）**
  - 原始依据：Cookie helper 使用 `Secure=false`，未显式设置 SameSite；写接口没有显式 CSRF 防护。`session_secret` 已有配置但当前会话 token 采用哈希查库，不能把该字段视为已启用的签名机制。
  - 工作：明确 HTTPS/反代可信边界，配置 Secure/HttpOnly/SameSite、CSRF、会话过期与轮换；清理或说明未使用的安全配置。
  - 验收：生产 HTTPS Cookie 标志正确；非允许来源的写请求失败；过期/退出/禁用会话不可用；配置与真实安全机制一致。依赖 P0-02。

- [ ] **P0-06 公开入口限流与资源配额（ingest / master，M0）**
  - 依据：指标 points/labels 已有单批限制，但身份元数据、注册、租户分配、事件/探测入口和连接总量缺少同等明确边界。
  - 工作：补齐请求体、身份字段、数组、时间戳及状态值校验；限制租户申请频率、Agent/worker 数量、写入速率和 SSE/gRPC 并发；保护 debug 入口。
  - 验收：超额/异常请求在数据库与缓存写入前拒绝，返回可识别状态；正常长连接不被误限；拒绝与限流可观测。配额按 P0-04 的可信身份计数。

- [ ] **P0-07 TLS 与生产网络边界（Agent / 服务装配 / deployments，M0）**

  - 工作：显式配置 TLS/开发明文模式，定义 TLS 终止位置；开发依赖绑定回环地址，生产限制数据库/Redis/ingest 内网访问；提供静态前端与反代示例。

## P1：实时链路可靠性与工程基线

- [ ] **P1-01 ACK 截止时间、有界缓冲与重连（Agent，M1）**
  - 依据：发送后同步 `Recv()`，仅使用运行上下文；失败后下一轮发送新批次，没有未确认队列。
  - 工作：为流/批次等待定义可取消期限，设计退避和抖动、有界缓冲、补传顺序、溢出丢弃策略；说明是否支持进程重启后恢复。
  - 验收：服务端不返回 ACK 时 Agent 不永久停采；断网恢复符合补传策略；长时间断网不使内存无界增长；停止进程能及时退出。与 P1-02 联合确定重试语义。

- [ ] **P1-02 批次幂等、乱序与时间语义（ingest / PG / Agent，M1）**
  - 依据：`last_seq` 直接更新；摘要和 Redis 历史以接收时间更新，重复或旧批次缺少防护。
  - 工作：定义 `(租户, host, agent实例, batch_seq)` 的幂等范围，区分采集时间、接收时间和存活时间；处理 Agent 重启、延迟补传及异常未来时间。
  - 验收：重复提交不增加历史点或重复业务效果；旧批次不覆盖新快照；补传不能把离线主机错误标为当前在线；并发写入结果一致。依赖 P0-04。

- [ ] **P1-03 PG / Redis 部分失败恢复与 ACK 语义（ingest / 数据层，M1）**
  - 依据：PG 提交后依次写 Redis 历史、最新快照、Pub/Sub，任一步失败会中断处理；离线更新也可能提交后发布失败。
  - 工作：明确 ACK 对应的持久化边界；设计可重试的投影/通知恢复机制，例如事务 outbox，并设置积压、重试与清理边界。
  - 验收：在各步注入失败后，重试能恢复约定的数据和通知，不重复应用状态；可查询积压和失败原因；Redis 重启不会造成永久不一致。依赖 P1-02/P1-07。

- [ ] **P1-04 SSE 初始同步、删除与慢连接（master-api / Web / event bus，M1）**
  - 依据：先查询状态/历史再订阅，存在丢更新窗口；删除事件没有 tenant，带租户的流直接跳过；每个 SSE 各自订阅 Redis。
  - 工作：设计订阅与快照衔接、版本校验和重新同步；删除携带可信租户；限制慢客户端积压与写等待。
  - 验收：首屏期间更新不会永久丢失；断线重连收敛到权威快照；删除同步到对应租户且不泄露其他租户；慢连接不阻塞其他用户。依赖 P0-01/P1-03。

- [ ] **P1-05 采样、离线与窗口配置一致性（Agent / ingest / Web，M1）**
  - 依据：离线阈值固定 15 秒、巡检 5 秒；服务装配把摘要窗口设为 60 点、TTL 2 小时；前端历史保留常量为 3600 秒。
  - 工作：明确可配置采样间隔、迟到容忍、离线阈值和实际历史时长；区分保留点数、TTL 与展示范围，避免前端展示超出可查询数据。
  - 验收：1 秒、5 秒及更长间隔下离线判断符合配置；窗口和时间标注一致；迟到和恢复路径可解释。

- [ ] **P1-06 全仓 CI 与关键回归（CI / 各模块，M1）**
  - 依据：当前 workflow 聚焦 Agent 多平台构建，未设置后端/前端/proto 的完整质量门禁。
  - 工作：配置 Go 测试/构建/格式校验、proto 校验/生成一致性、Web typecheck/build；补关键授权、批次重试、SSE 和采集契约回归。涉及 Docker 的变更增加 Compose 与 smoke。
  - 验收：后端、前端、协议改动均触发相应检查；格式漂移/生成漂移导致失败；不会因 paths 过滤漏掉服务变更；跨平台构建和真实采样验证分别记录。

- [ ] **P1-07 存量数据库迁移与备份恢复（数据层 / deployments，M1）**
  - 依据：初始化 SQL 只在新卷执行，已有单独升级 SQL，但未形成统一迁移版本和执行流程。
  - 工作：建立有序迁移、失败恢复、重复执行策略及备份/恢复手册；所有 schema 改动同步 init.sql 和升级脚本。
  - 验收：空库初始化与存量升级得到一致结构；升级失败能恢复；备份恢复后的主机/用户/业务数据可查询；不依赖删除数据卷升级。

- [ ] **P1-08 平台可观测性与服务生命周期（所有服务，M1）**
  - 依据：目前主要是日志、健康 JSON 和进程内计数；HTTP Server 未配置请求读取边界；gRPC GracefulStop 未与关闭上下文超时联动。
  - 工作：区分存活/就绪，记录写入和 ACK 延迟、错误率、连接数、缓存/DB 故障及重试积压；设置 HTTP 请求读取边界和 gRPC 强制关闭兜底，兼容 SSE 长连接。
  - 验收：依赖不可用时就绪状态准确；进程能在规定关闭期限内退出；慢请求受限；SSE 不受普通请求超时误伤；日志不包含凭据。

- [ ] **P1-09 公共仓储与旧实现收敛（pkg / master-api，M1）**
  - 依据：生产装配使用 `pkg/hostruntime/repository`，master-api 内仍有同类仓储和测试。
  - 工作：核对引用和契约差异，将仍有价值的行为测试迁到公共仓储，再删除无运行用途的重复实现。
  - 验收：主机状态、窗口和事件各有明确实现入口；没有遗留引用；原有有效行为得到覆盖；数据结构与公共接口保持兼容。

- [ ] **P1-10 可复现开发、生产交付与文档（deployments / docs，M1）**
  - 依据：config 目录被忽略，配置模板主要在文档；安装命令混用 main/master；README 提及的 PWA 路由当前未接入；Web 部署脚本绑定本机路径。
  - 工作：提供可提交且不含秘密的配置模板；统一安装分支/发布版本与下载失败行为；完善参数化部署、反代/SSE、健康检查、回滚和运维手册；同步 README 与真实路由。
  - 验收：干净检出可按文档完成本地链路；部署不依赖作者机器目录；安装校验和不被绕过；文档中的命令、入口与当前代码一致。生产部分依赖 P0-07/P1-07。

- [ ] **P1-11 指标质量、强类型协议与前端竞态（Agent / ingest / Web，M1）**
  - 依据：扩展采集支持降级状态，兼容摘要缺失时仍可能填零；强类型字段未完整贯通接入；实时 Hook 的请求取消、tenant 切换及事件解析需覆盖。
  - 工作：定义缺测/超时/有效零值与首次速率样本语义；明确 points 和强类型字段的主从/兼容规则；旧租户请求不能覆盖新页面，异常事件触发受控恢复。
  - 验收：采集器失败不形成假零或错误告警；协议不一致有确定处理方式；快速切换租户不会残留旧主机/快照；坏 JSON 不破坏后续刷新。依赖 P1-05/P0-01。

## P2：产品闭环

- [ ] **P2-01 core-worker 状态融合（core / 数据层，M2）**：建立可幂等运行的计算循环，区分 Agent、可达性、服务和 overall 状态，定义单一写入职责与并发保护。验收：Agent 离线不直接等同于所有探测不可达，状态原因与版本可追踪，重复计算不重复生成事件。依赖 P1-02/P1-03/P1-05/P1-08/P1-11。

- [ ] **P2-02 告警规则与生命周期（core / master / 数据层，M2）**：提供规则管理，先覆盖离线和 CPU/内存/磁盘阈值；实现持续时间、恢复、去重、列表/详情、确认和审计。验收：持续异常只产生一个活动告警，恢复关闭且保留时间线，确认按角色和租户授权。依赖 P2-01/P0-03/P1-07。

- [ ] **P2-03 维护窗真实生效（core / master / Web，M2）**：完成范围校验、列表/更新/停用、时间边界和告警抑制策略。验收：维护期间按策略抑制，结束后恢复计算，窗口重叠可解释，所有操作使用会话租户。依赖 P2-02/P0-03。

- [ ] **P2-04 告警通知与处置界面（core / master / Web，M2）**：接通至少一个通知渠道，定义重试、去重、失败记录、配置秘密管理与告警页面。验收：触发/恢复通知可追踪，通知失败不丢告警，重试不重复轰炸；可配置 webhook 时先限制出站目标。依赖 P2-02/P1-08。

- [ ] **P2-05 探测结果持久化与查询（ingest / master / 数据层，M3）**：校验真实租户/任务/目标/worker，保存结果、延迟和错误，支持分页与保留清理。验收：查询可定位执行者与采样时间；重复/越权结果被拒绝；成功 ACK 符合持久化承诺。依赖 P0-04/P1-02/P1-03/P1-07。

- [ ] **P2-06 探测调度、SSRF 防护与状态联动（core / probe / Web，M3）**：管理 HTTP 目标，替换固定 ID，实现领取/租约/并发/超时/重试；限制 scheme、端口、内网/元数据地址及重定向，校验 DNS 解析后的实际连接目标。私有网络探测需显式授权与隔离。验收：worker 失联后任务可重新领取；重复执行不重复计入结果；未授权目标被拦截；结果更新状态与告警。依赖 P2-01/P2-02/P2-05。

- [ ] **P2-07 Agent 事件生产、存储和检索（Agent / ingest / master，M3）**：先选定最小事件场景，建立时间、类型、严重性、去重键、分页、保留和内容校验。验收：事件从产生到查询可追踪；只计数不落库的现状被替换；无凭据/敏感明细泄漏。依赖 P0-04/P0-06/P1-02/P1-07。

- [ ] **P2-08 指标目录与历史查询契约（master / Web，M4）**：提供按 name+labels 查询的目录、单位、类型、时间范围、步长、聚合及缺测语义。验收：能表达设备/挂载点/网卡维度；查询点数和时间范围有上限；租户范围来自可信授权。依赖 P0-01/P1-11；完整验收依赖 P2-09。

- [ ] **P2-09 长期时序、降采样与动态序列配额（数据层 / ingest / core，M4）**：测量写入量/序列量后选择 PG 长期模型或专用时序存储；先存固定摘要，再开放受限动态历史；制定租户/主机配额、保留、压缩、清理与备份。验收：保留到期能删除，超基数受控，查询有成本边界，恢复流程可用。依赖 P1-03/P1-07/P1-08/P2-08 的契约；先完成契约再实现存储，最后联合验收。

- [ ] **P2-10 主机生命周期、分组与配置管理（master / Agent / Web，M4）**：补下线/删除、分组/标签、Agent 版本和采样配置管理，明确删除后上报是否重建、历史与告警保留规则及配置确认。验收：跨租户引用拒绝；删除正确推送并清理页面；被撤销 Agent 不自动复活；配置下发可确认/回滚。依赖 P0-03/P0-04/P1-04/P2-02；历史清理结合 P2-09。

## 验收与状态维护

实施时按改动选择仓库现有目标：Go 变更用 `make test` / `make build`，协议用 `make proto-check`，前端用 `make web-typecheck` / `make web-build`，Docker 和链路变更用 `make compose-config`、`make docker-up`、`make smoke`、`make smoke-agent` 与 `make docker-down`。这些命令不能替代条目中的越权、故障注入、恢复或容量验收。

完成条目时附 Issue/PR、实际验证命令与结果，并更新现状文档。仅有 SQL 表、API 入口、计数增长、构建成功或健康检查成功，不足以勾选业务闭环任务。

## 安全提醒

本次清单不新增运行时代码。P0 记录的是代码梳理发现的既有风险；后续每个实现 PR 应检查租户授权、凭据与日志、请求和连接边界、迁移安全及私有数据暴露。探测 URL、通知 webhook、动态历史和 PWA 缓存必须随功能一并设计安全边界。
